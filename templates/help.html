Reference guide for using the DynDNS service and web interface.

Check your public IP address as seen by the DynDNS server. No authentication required.

GET /nic/checkip
Response Formats
  • HTML (default): Current IP Address: 203.0.113.1
  • Plain text: add ?format=plain to get just the IP address
Examples
# HTML format (like checkip.dyndns.com)
curl "https://dyndns.example.com/nic/checkip"

# Plain text
curl "https://dyndns.example.com/nic/checkip?format=plain"

Useful for clients that need to detect their external IP before sending an update.

This service implements the DynDNS v2 protocol. DNS records are updated via a single HTTP GET request:

GET /nic/update?hostname=<FQDN>&myip=<IP>
Parameters
ParameterRequiredDescription
hostnameYesFully qualified domain name to update (e.g. home.dyn.example.com). Comma-separated for multiple.
myipNoIP address to set. If omitted, the client's source IP is used.

The updatetype parameter is deprecated and ignored. All backends configured for the hostname's domain are updated automatically.

Authentication

Use HTTP Basic Auth with your DynDNS username and password. This is the recommended method.

curl -u username:password "https://dyndns.example.com/nic/update?hostname=home.dyn.example.com&myip=203.0.113.1"

Query parameter authentication (username / password) is supported for compatibility but not recommended — credentials may appear in server logs.

DNS records can be deleted via a single HTTP GET request:

GET /nic/delete?hostname=<FQDN>[&myip=<IP>]
Parameters
ParameterRequiredDescription
hostnameYesFully qualified domain name to delete (e.g. home.dyn.example.com). Comma-separated for multiple.
myipNoIf provided, only delete the record matching this IP (A or AAAA). If omitted, both A and AAAA records are deleted.

Authentication is the same as the update endpoint (HTTP Basic Auth preferred).

curl -u username:password "https://dyndns.example.com/nic/delete?hostname=home.dyn.example.com"

Returns good if records were deleted, nochg if no matching records existed.

The update endpoint returns one line per hostname with a status code followed by the IP address:

CodeMeaning
goodDNS record was created or updated successfully on at least one backend.
nochgIP address has not changed on any backend; no update performed.
badauthInvalid username or password.
notfqdnThe hostname is not a valid fully qualified domain name.
nohostThe hostname is not registered to your account.
dnserrDNS backend returned an error while processing the update.
abuseToo many requests. Rate limit exceeded.
911Server-side error (missing credentials, invalid IP, or internal failure).

Navigate to Users in the navigation bar to manage user accounts.

  • Create — Click "New User" and fill in username, password, role, and active status.
  • Edit — Click a username to change their password, role, or active status. Leave the password field empty to keep the current password.
  • Hostnames — Click "Hostnames" to manage which hostnames a user can update.
  • Activate / Deactivate — Uncheck "Active" to disable a user without deleting them. Deactivated users cannot log in or update DNS records.
  • Web Login — Controls whether the user can log in to the web UI. Disable this for API-only accounts that should not have web access; DynDNS API access is unaffected. New users default to web login disabled.
  • Delete — Permanently removes the user and all their hostname registrations. You cannot delete your own account.
Roles
  • admin — Full access to all users, domains, backends, credentials, and events.
  • user — Can register hostnames, update DNS records, view own events, and change own password.

Navigate to Domains in the navigation bar. Domains are global zones that users can register hostnames under.

  • Add Domain — Enter the parent domain (e.g. dyn.example.com). Users can then register hostnames under it (e.g. home.dyn.example.com).
  • Backends — Each domain can have one or more backends (aws, nsupdate, hetzner). When a hostname is updated, all backends for its domain are called.
  • Credentials — Configure backend credentials per domain via the "Configure" button. Credentials are shared across all users of that domain.
  • Delete — Removes the domain, all its backends, and all registered hostnames.

Each domain backend has its own set of credentials, configured from the domain edit page.

Credentials are Fernet-encrypted at rest in the database. The encryption key is set via the FERNET_KEY environment variable. If this key is lost, all stored credentials become unrecoverable.

Navigate to Rate Limits in the navigation bar to configure request throttling for the /nic/update and /nic/delete endpoints.

Limits are database-backed and shared across all gunicorn workers. When a user exceeds the limit the endpoint returns abuse.

Global defaults

Set a per-minute and per-hour request limit that applies to all users. The built-in fallback is 30 requests/minute and 500 requests/hour.

Per-user overrides

Click a username in the "Add Override" section to set a custom limit for that user. Overrides take precedence over the global defaults. Remove an override to revert to the global limit.

Navigate to Health Checks in the navigation bar. The health checker periodically resolves all tracked hostnames and compares the DNS result against the last known IP stored in the database.

Statuses
StatusMeaning
okDNS record matches the last known IP.
mismatchDNS record exists but resolves to a different IP.
missingNo DNS record found for the hostname.
errorDNS resolution failed (no nameservers, timeout, etc.).
Configuration

Click Configure to enable/disable automatic checks and set the interval (1–1440 minutes). Click Run Now to trigger an immediate check. Results are retained until the next run.

Non-ok results are surfaced as a warning panel on the admin Dashboard. Mismatches and missing records also emit WARNING log messages (useful for Loki alerting).
